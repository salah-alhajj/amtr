## 1. مبادئ المعمارية المعتمدة
تم اعتماد معمارية البرمجيات النظيفة (Clean Architecture) لضمان أن قواعد الأعمال (Business Rules) تظل مستقلة تماماً عن أي إطار عمل واجهات (Flutter UI) أو تفاصيل قواعد البيانات والتخزين الخارجي.

### 2. توزيع الطبقات في كل ميزة (Feature Slicing)
لكل ميزة من ميزات التطبيق (customers, orders, shipments, settings, backup) هيكل ثلاثي صارم:
- **طبقة النطاق (Domain Layer):**
  - الكيانات (Entities): نماذج بيانات نقية خالية من أي توابع تحويل JSON أو اعتماديات على حزم خارجية.
  - الواجهات المستودعية (Repository Interfaces): عقود مجردة (Abstract Contracts) تحدد العمليات المتاحة دون معرفة كيفية تخزينها.
- **طبقة البيانات (Data Layer):**
  - نماذج البيانات (Models): تمثيل الجداول ومحولات `toMap()` و `fromMap()` للتفاعل مع SQLite.
  - مصادر البيانات (Data Sources): الاتصال المباشر بقاعدة البيانات المحلية.
  - تنفيذ المستودعات (Repository Implementations): تجسيد العقود وتحويل البيانات الخام إلى كيانات نطاقية.
- **طبقة العرض والتقديم (Presentation Layer):**
  - إدارة الحالة (Bloc): استقبال الأحداث وإصدار الحالات دون بناء كود اصطناعي.
  - الشاشات (Screens): واجهات المستخدم الرئيسية.
  - الودجتس المتخصصة (Widgets): مكونات بصرية حصرية للميزة داخل مجلد `widgets/`.

| الطبقة | المسؤولية الأساسية | التبعيات المسموحة |
| :--- | :--- | :--- |
| Domain | قواعد البزنس والكيانات والعقود | نقية 100% لا تعتمد على أي طبقة أخرى |
| Data | الوصول لقاعدة البيانات ومصادر البيانات | تعتمد حصرياً على عقود الـ Domain |
| Presentation | الرسوم، التفاعل مع المستخدم، التقاط الأحداث | تعتمد على Domain وتستدعي UseCases/Bloc |
